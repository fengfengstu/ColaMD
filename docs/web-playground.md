# 网页体验版（`/try/`）

一个纯网页的 ColaMD 体验页：能打字，能实时切换 12 个主题，用一份样张展示排版。

**它是什么**：同一个编辑器内核（Milkdown / ProseMirror）＋ 同一套主题 CSS，去掉桌面外壳后编成的静态页面。不是截图，也不是模拟。

**它不是什么**（刻意不做，见 design.md 的产品边界）：不读写本地文件、不做实时同步、没有标签页 / 文件列表 / 大纲 / 查找 / 导出 / 图表 / 公式 / 字体设置。网页版演示不了产品最核心的「本地优先」，所以页面上有一行固定的说明，并给下载桌面版的入口。

## 为什么这么便宜

编辑核心对桌面能力的依赖只有四处，而且都是可选调用：

| 模块 | `window.electronAPI` 出现次数 |
| --- | --- |
| `src/renderer/editor/*.ts` | 4（其中 3 处带 `?.`） |
| `src/renderer/themes/*.ts` | 1 |

所以网页版**不需要 stub、不需要给渲染层打桩、不改一行桌面代码**：它是一个独立入口（`src/web/`），只 import 编辑器内核与主题 CSS。

## 怎么构建与本地预览

```bash
npm run build:web        # 产出 dist-web/（已加进 .gitignore）
npm run preview:web      # 本地 http://localhost:4173/
```

构建产物实测：JS 751KB（gzip 229KB）＋ CSS 61KB（gzip 15KB）；KaTeX 字体是 CSS 引用，只在使用公式时才下载（本页不涉及）。

## 规矩

1. **同一份源码，永不分叉**：网页版 import 的是 `src/renderer` 里的编辑器与主题，改动只允许发生在 `src/web/`（页面外壳）里。想改编辑器行为，改桌面版用的那份。
2. **不把桌面能力搬进网页版**：`src/web/` 里不出现 `window.electronAPI`。要展示某个桌面能力，就在页面上说明它属于桌面版。
3. 页面自身的工具栏也用主题变量（`--bg-color` / `--chrome-bg-hover` / `--link-color`），所以换主题时整页一起变。

## 已知取舍（MVP）

- 切换语言会重新载入样张，用户此刻改过的内容会被替换掉。要保留就得先做「是否已编辑」判断，这一版没做。
- 没有「海报式懒加载」：`/try/` 是一个独立目的地，页面直接加载编辑器。若以后把它嵌进首页 hero，再改成点击后再 `import()`。
- 窄屏可用，但体验以桌面为主。
